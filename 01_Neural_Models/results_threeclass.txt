======================================================================
OPTIONAL DIAGNOSTIC - adding a constant to every logit
======================================================================
max |softmax(z) - softmax(z + 100)| = 5.275e-11

The probabilities are unchanged apart from floating-point roundoff,
because exp(z_k + c) / sum_j exp(z_j + c) cancels the factor exp(c)
in the numerator and the denominator.

A naive implementation nonetheless breaks, because exp() of a large
logit overflows before the cancellation can happen:
  naive exp(z)/sum(exp(z)) on z = [1000.0, 1001.0, 1002.0]  ->  [nan, nan, nan]
  torch.softmax on the same z                      ->  [0.090031, 0.244728, 0.665241]

Stable implementations subtract max_j z_j first.  That shift leaves
the result mathematically identical, by the cancellation above, but
makes the largest exponent exp(0) = 1, so nothing overflows.

======================================================================
SCALING REMARK (Task 5 'Think About It')
======================================================================
Treating next-token prediction as classification over a vocabulary
leaves the following unchanged as the number of classes grows from 3
to tens of thousands: the softmax normalisation, the cross-entropy
loss, and the gradient p - y.  What changes is everything around it -
the output matrix becomes (vocabulary x hidden) and dominates the
parameter count, the normalising sum over classes becomes the
expensive part of each step, the targets become sparse one-hot rows
stored as indices, and the context is no longer two binary inputs but
a long sequence requiring an architecture that can represent it.
