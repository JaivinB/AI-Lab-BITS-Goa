Note what makes this termination sound rather than lucky: the
reachable state space is finite and already-visited states are never
re-expanded, so breadth-first search exhausts it and stops.  A
planner that re-expanded states would loop here for ever, moving the
robot a -> b -> a -> b without ever failing.

# TASK 5 - generated explanation vs independent verification
######################################################################

The laboratory sheet suggests reasoning about the sequence

    Move(a,b),  PickUp(Package,b),  Move(b,c),  Drop(Package,c)

It reads perfectly plausibly: go to b, pick the package up, carry it
to c, put it down.  An LLM asked to justify it can produce a fluent
explanation of exactly that story.  Replaying it against the actual
preconditions:

    step 2: PickUp(Package,b) not applicable - missing ['At(Package,b)'], forbidden present []
    final state {At(Package,a), At(Robot,b)} does not entail the goal {At(Package,c)}

Step 2 fails: PickUp(Package,b) requires At(Package,b), and the
package never moved - it is still at a, because Move affects only
the robot's location.  The sequence is invalid, and no amount of
fluency in the explanation changes that.

The correct plan picks the package up BEFORE moving:
    PickUp(Package,a), Move(a,b), Move(b,c), Drop(Package,c)
    problems: none - plan valid
    final state: {At(Package,c), At(Robot,c)}

Which to trust: the independently executed state transitions.  The
explanation and the plan come from the same source, so an error in
the plan tends to be reproduced in the explanation - the two agree
with each other rather than with the domain.  The replay consults
the action definitions instead, and is capable of disagreeing.
